# Вторая копия бота

Инструкция для случая «развернуть бота для другого канала». Техническую
часть держит у себя один человек, редакторам достаточно Телеграма: они
видят карточки в чате и жмут кнопки.

Копия обязана быть полностью самостоятельной. Общая база или общий бот
у двух каналов приведут к тому, что посты одного уедут в другой.

## Что завести (всё бесплатно)

| Что | Где | Зачем |
|---|---|---|
| Бот Телеграма | @BotFather → `/newbot` | свой токен, иначе два канала делят одного бота |
| Канал и чат редакторов | Телеграм | бот - админ канала с правом публикации, участник чата |
| Проект Supabase | supabase.com | своя база и свой вебхук |
| Репозиторий | копия этого | свои секреты и свои кроны |
| Ключ Gemini | aistudio.google.com | **отдельный гугл-аккаунт**: квота считается на аккаунт |

Ключ Gemini не привязан к стране: запросы уходят с раннера GitHub, а не с
машины владельца ключа. Достаточно один раз получить строку ключа.

## Секреты репозитория

Settings → Secrets and variables → Actions → Secrets:

| Секрет | Откуда |
|---|---|
| `BOT_TOKEN` | @BotFather |
| `CHANNEL_ID` | `@имя_канала` |
| `EDITORS_CHAT_ID` | id чата редакторов (отрицательное число) |
| `EDITOR_USER_IDS` | id тех, чьи команды слушать, через запятую |
| `SUPABASE_URL` | Dashboard → Project Settings → API |
| `SUPABASE_SECRET_KEY` | там же, формат `sb_secret_...` |
| `SUPABASE_DB_URL` | Dashboard → Connect → **Session pooler** |
| `SUPABASE_ACCESS_TOKEN` | supabase.com/dashboard/account/tokens - для деплоя функции |
| `GEMINI_API_KEY` | AI Studio, **без привязки карты** |
| `TG_WEBHOOK_SECRET` | любая случайная строка |
| `GH_PAT` | fine-grained токен с правом Actions: write - нужен только для `/more` |
| `GEMINI_API_KEYS` | необязательно: несколько ключей через запятую, бот их ротирует |
| `NARA_API_KEY`, `EUROPEANA_API_KEY` | необязательно: включают ещё два источника |

Variables (соседняя вкладка): `INSTANT_PUBLISH` = `false` - боевой режим,
публикация по расписанию. `true` - одобренное уходит в канал сразу, удобно
для теста.

## Порядок запуска

1. **Миграции.** Actions → `setup-db` → Run workflow. В Table Editor должны
   появиться `candidates`, `seen_hashes`, `heartbeats`, `settings`.
2. **Бэкфилл архива канала.** Пуш в `.github/verify.trigger` со словом `fast`.
   Скрипт проходит `t.me/s/<канал>` и запоминает хэши уже вышедших фото -
   иначе первая же партия будет наполовину из повторов.
3. **Вебхук.** Пуш в `.github/deploy-webhook.trigger`. Воркфлоу сам положит
   секреты в функцию, задеплоит её, пропишет вебхук в Телеграме и проверит
   ответ.
4. **Диагностика.** Пуш в `.github/diag.trigger`. В логе шага «Куда постим и
   где чат» должны быть правильные названия канала и чата, а в правах бота -
   `can_post_messages: true`.
5. **Первая партия.** Команда `/more` в чате редакторов.
6. **Режим.** `/schedule` - времена публикаций, `/auto` - автопостинг без
   одобрения. `/status` показывает и то и другое.

## Что поправить под новый канал

- `config.yaml` → `channel`: имя канала, подпись, ссылка.
- `config.yaml` → `publish.times`: стартовое расписание (дальше меняется
  через `/schedule` прямо из бота).
- `config.yaml` → `sources`: темы и годы под тематику канала.
- `src/caption.ts` → `FEW_SHOT`: **самое важное**. Там лежат настоящие посты
  канала-образца, по ним модель копирует тон. Для другого канала их надо
  заменить его собственными постами, иначе стиль будет чужой.
  Готовые тексты можно выгрузить: пуш в `.github/report.trigger` со словом
  `style` - скрипт достанет посты прямо из `t.me/s`.
- `src/scoring.ts` → `SCORING_CRITERIA`: что считать интересным.

## Обновления из основного репозитория

```bash
git remote add upstream <url основного репозитория>
git fetch upstream
git merge upstream/<ветка>
```

Конфликты будут ровно там, где копия отличается специально: `config.yaml`
и блок примеров в `src/caption.ts`. Свою версию этих файлов и оставляем.

## Что нужно редактору

Ничего, кроме Телеграма. Его id добавляется в `EDITOR_USER_IDS` - и он
видит карточки, жмёт кнопки, пишет команды. Остальное живёт на серверах и
внимания не требует.
